# Large 2D canvas backing route

This is a source-only investigation of the immutable BUILD48 alpha captures. It does not sample, alter, or fit captured pixels. Run `python3 Scripts/native-render-parity/source-canvas-clip/minification-source/report.py` from the worktree to rebuild `build/native-render-parity/source-canvas-minification/source-route.json`. The report hashes the six original canvas inputs and 19 pinned source files.

The recorded large canvas is 412×527 source pixels, displayed at CSS 91×121 on DPR3, producing a 273×363 raster. The two small controls each have a 20×20 bitmap and are enlarged. Under the pinned normal compositing policy and accelerated-2D defaults, their intrinsic areas fall on opposite sides of the 5,000-pixel own-layer threshold. This threshold selects a backing route; it does not define an image-filter kernel.

The relevant source revision is `dd5fe1011df7e3438ac4889356abcab7681df46d`:

- [CanvasBase](https://github.com/WebKit/WebKit/blob/dd5fe1011df7e3438ac4889356abcab7681df46d/Source/WebCore/html/CanvasBase.cpp#L279) creates the canvas bitmap with resolution scale 1. `willReadFrequently` and acceleration eligibility select its backend.
- [CanvasRenderingContext](https://github.com/WebKit/WebKit/blob/dd5fe1011df7e3438ac4889356abcab7681df46d/Source/WebCore/html/canvas/CanvasRenderingContext.cpp#L106) does not delegate CoreGraphics 2D display directly. [RenderLayerBacking](https://github.com/WebKit/WebKit/blob/dd5fe1011df7e3438ac4889356abcab7681df46d/Source/WebCore/rendering/RenderLayerBacking.cpp#L125) therefore selects `CanvasPaintedToLayer` for accelerated 2D, rather than `CanvasAsLayerContents`.
- [RenderLayerCompositor](https://github.com/WebKit/WebKit/blob/dd5fe1011df7e3438ac4889356abcab7681df46d/Source/WebCore/rendering/RenderLayerCompositor.cpp#L3891) admits that painted canvas to an own composited layer at sufficient intrinsic area. [RenderLayerBacking](https://github.com/WebKit/WebKit/blob/dd5fe1011df7e3438ac4889356abcab7681df46d/Source/WebCore/rendering/RenderLayerBacking.cpp#L606) enables acceleration for the canvas backing even when compositor-wide acceleration is disabled.
- [The contents filter branch](https://github.com/WebKit/WebKit/blob/dd5fe1011df7e3438ac4889356abcab7681df46d/Source/WebCore/rendering/RenderLayerBacking.cpp#L935) applies to direct layer contents. It does not specify the filter for a 2D painted canvas. Since CSS dimensions differ from the bitmap, [the unscaled-bitmap optimization](https://github.com/WebKit/WebKit/blob/dd5fe1011df7e3438ac4889356abcab7681df46d/Source/WebCore/rendering/RenderLayerBacking.cpp#L3383) is unavailable; normal page/device backing scale remains active.
- [HTMLCanvasElement](https://github.com/WebKit/WebKit/blob/dd5fe1011df7e3438ac4889356abcab7681df46d/Source/WebCore/html/HTMLCanvasElement.cpp#L640) paints the buffer into the snapped destination. [GraphicsContext](https://github.com/WebKit/WebKit/blob/dd5fe1011df7e3438ac4889356abcab7681df46d/Source/WebCore/platform/graphics/GraphicsContext.cpp#L383) passes its native image to the platform draw. Deferred contexts copy the native image; ordinary contexts can retain a reference.
- [ImageQualityController](https://github.com/WebKit/WebKit/blob/dd5fe1011df7e3438ac4889356abcab7681df46d/Source/WebCore/rendering/ImageQualityController.cpp#L104) returns no override for `image-rendering:auto`. [GraphicsContextCG](https://github.com/WebKit/WebKit/blob/dd5fe1011df7e3438ac4889356abcab7681df46d/Source/WebCore/platform/graphics/cg/GraphicsContextCG.cpp#L210) begins with the inherited CGContext interpolation quality. On iOS its image draw disables edge antialiasing, rounds destination edges through the user-to-device transform, translates to the destination, flips Y, and calls `CGContextDrawImage`. Full-source drawing avoids the crop/subimage branches.
- [IOSurface](https://github.com/WebKit/WebKit/blob/dd5fe1011df7e3438ac4889356abcab7681df46d/Source/WebCore/platform/graphics/cocoa/IOSurface.mm#L490) constructs the accelerated drawing context using a platform-private backend. [RemoteLayerBackingStore](https://github.com/WebKit/WebKit/blob/dd5fe1011df7e3438ac4889356abcab7681df46d/Source/WebKit/Shared/RemoteLayerTree/RemoteLayerBackingStore.mm#L265) uses BGRA8 for transparent SDR layers. [WKWebView's visible-window snapshot](https://github.com/WebKit/WebKit/blob/dd5fe1011df7e3438ac4889356abcab7681df46d/Source/WebKit/UIProcess/API/ios/WKWebViewIOS.mm#L4573) reads the composited display through the render server.

## Diagnostic handoff

The source-motivated public native control is an on-screen UIView or CALayer delegate that paints the original CGImage into its own CSS-sized, DPR3 backing, then captures the visible hierarchy. Its image draw should preserve inherited interpolation quality, disable edge antialiasing, and use the same top-left image flip. Record the public CGContext quality, CTM, bitmap properties, view/layer dimensions, contents scale, viewport, and capture scale. The 91×121 bounds already map to integer device edges, so the source's edge rounding leaves them unchanged.

A public bitmap CGContext draw and a direct `CALayer.contents` texture test exercise different routes. Their failures do not establish what the accelerated painted-layer backend does. The public view control is still a diagnostic: exact captured pixel comparison is required before adopting it.

## Limits

The actual capture does not expose WebKit's private layer tree or backing strategy. The source prediction is conditional on runtime acceleration and compositing defaults matching this pinned revision. CoreGraphics IOSurface filter weights and render-server composition are closed platform implementations; these files provide no exact tap equation. No private API is proposed for production, and this report makes no claim that the remaining large-mask pixels are equal.
