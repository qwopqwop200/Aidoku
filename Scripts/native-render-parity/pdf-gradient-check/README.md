# Native PDF gradient geometry check

Run from the worktree root:

```sh
swiftc -O Aidoku/Core/Translation/NativeEngine/Overlay/NativeTranslationPDFCapture.swift Scripts/native-render-parity/pdf-gradient-check/main.swift -o build/native-render-parity/native-pdf-gradient/check
build/native-render-parity/native-pdf-gradient/check Scripts/native-render-parity/pdf-gradient-check/fixtures.json
```

The 14 fixtures retain measured tile dimensions and pattern/vector decisions from
nine frozen WebKit PDF captures. They exercise the actual production helper;
passing this check does not establish final PNG equality.

The device-grid snapping and repeated tile containment decision follow the
original geometry policy documented in these primary sources:

- [BackgroundPainter.cpp](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/rendering/BackgroundPainter.cpp)
- [Image.cpp](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/platform/graphics/Image.cpp)
- [GradientImage.cpp](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/platform/graphics/GradientImage.cpp)
- [LayoutPoint.h](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/platform/graphics/LayoutPoint.h)

The native implementation paints with Core Graphics directly; these sources are
used only to verify the capture policy. The oracle's renderer and reference source
archive remain unchanged.

The pattern raster check calls the actual native helper and compares every
embedded RGB and alpha-mask byte from both light and dark gradient tiles:

```sh
python3 Scripts/native-render-parity/pdf-gradient-check/raster-check.py --reference /absolute/path/to/frozen-PDF-captures
```

The reference directory must contain `horizontal-korean.pdf` and
`dark-translucent.pdf` from the frozen capture. It defaults to the local captured
artifacts at `build/native-render-parity/export-gradient-alpha`. No reference
pixels or PDF bytes are generated by the native candidate.
