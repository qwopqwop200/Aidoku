# Restoration RGBA image transport parity

Run `python3 Scripts/native-render-parity/restoration-image-transport/run.py`. This compiles the actual production `NativeRestorationPixels.image()` method **verbatim** inside a minimal host struct containing its existing width/height/RGBA properties. The original bitmap algorithm is neither mocked nor rewritten. A hidden local macOS `WKWebView` supplies actual `putImageData`, PNG `toDataURL`, image decode, `drawImage`, and `getImageData` outputs. No network, external images, Xcode app build, or production edits are required.

Four independent patterns contain canonical zero-RGB transparent/opaque masks, **alpha-zero pixels retaining nonzero RGB**, constant alpha 128, and alpha values 0/1/31/64/127/128/200/254/255. Each pattern passes through direct image drawing and PNG encoding/decoding, then identity/upscale/downscale drawing, white-background scaling, and fractional colored-background scaling. Every RGBA byte is compared without tolerance. The production CGImage method and two separate host-only proposed transports are compared against the same 40 Canvas cases.

The first actual run confirmed a defect: the production method declares raw, unpremultiplied kernel pixels as `premultipliedLast`. Only **15/40** outputs matched Canvas; maximum channel delta was **255**. A native PNG pixel with alpha 128 became `[72,179,223,128]` where Canvas produced `[36,90,112,128]`. Transparent input `[19,61,101,0]` stayed colored in the native direct raster where Canvas produced `[0,0,0,0]`, and under fractional drawing changed an opaque colored-background pixel from Canvas `[40,117,197,255]` to native `[44,129,216,255]`.

Both independent proposed transports matched **40/40 exactly**: declare the untouched raw RGBA CGImage as `CGImageAlphaInfo.last`, or first canonicalize RGB with `(channel * alpha + 127) / 255` and declare the converted buffer premultiplied. The alpha-last declaration preserves the existing raw pixel-buffer contract and avoids rewriting kernel output. These candidate variants are diagnostic host methods; the script does not edit production.

The report records the exact production method/source hashes, per-case delta and first differing pixel, raw raster pairs, actual WebKit version and DPR, and saved WebKit/native PNGs. Evidence is under `build/native-render-parity/restoration-image-transport`. For a production fix recheck, pass `--output build/native-render-parity/restoration-image-transport-after-fix` to preserve the original defect evidence. This proves image transport on the stated host/backend; it does not establish complete native/WebKit glyph or final whole-page identity.
